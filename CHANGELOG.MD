# Changelog

## [Unreleased]

Переработан DI-контейнер (`pkg/di`). Подробности: [pkg/di/README.MD](pkg/di/README.MD).

### ⚠️ Изменения поведения

Сигнатуры `Register` и `Resolve` не изменились. Сервисы, которые регистрируют только
конкретные типы (`*Struct`) и резолвят их тем же типом, изменения не затрагивают.

- **Регистрация по статическому типу.** Зависимость сохраняется под типом `T`, а не под
  динамическим типом значения. `var s Svc = &Impl{}; di.Register(c, s)` теперь резолвится
  через `Resolve[Svc]` и **больше не находится** через `Resolve[*Impl]`.
- **Неверная сигнатура фабрики - паника в `Register`.** Поддерживаются только `func() T`
  и `func() (T, error)`. Функции с аргументами и прочие сигнатуры раньше молча принимались
  и падали только на `Resolve`, теперь сервис упадёт при старте. `nil`-функция - тоже паника.
- **Побеждает последняя регистрация.** Новая фабрика заменяет инстанс, созданный предыдущей
  фабрикой или зарегистрированный ранее (раньше оставался старый объект).
- Ошибка `wrong dependency type: X` больше не возникает.

### Добавлено

- Фабрики `func() (T, error)`: ошибка возвращается из `Resolve`, результат не кешируется,
  следующий `Resolve` повторяет вызов.
- Именованные зависимости: `RegisterNamed`, `ResolveNamed`, `MustResolveNamed`, `HasNamed`.
- `MustResolve[T]` - резолв с паникой вместо ошибки.
- `Has[T]` - проверка регистрации без вызова фабрики.
- `Container.Close(ctx)` - закрывает объекты, созданные фабриками, в обратном порядке создания
  (`Shutdown(ctx) error`, `Close() error`, `Close()`). Готовые инстансы из `Register` не закрываются.
  Вызывается автоматически в `app.WaitForShutdown()` после stop-хуков.
- Ошибки для `errors.Is`: `ErrDependencyNotFound`, `ErrFactoryFailed`, `ErrCircularDependency`.
- Обнаружение циклических зависимостей между фабриками, в том числе между горутинами:
  `circular dependency: *A -> *B -> *A`.

### Исправлено

- Зависимость, зарегистрированная фабрикой под интерфейсом, резолвилась только один раз:
  повторный `Resolve` возвращал `dependency not found`.
- Интерфейсная переменная, переданная в `Register`, не находилась через `Resolve` по интерфейсу.
- Фабрика при конкурентном первом `Resolve` могла вызываться несколько раз, а разные горутины -
  получать разные объекты. Теперь фабрика вызывается ровно один раз, остальные ждут её результат.
- Циклическая зависимость между фабриками вызывала переполнение стека и падение процесса.
- Паника при `Register`/`Resolve` nil-интерфейса и при фабрике, вернувшей nil-интерфейс.
- Непонятная паника `index out of range` при регистрации функции без возвращаемого значения.
